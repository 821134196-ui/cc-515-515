# 毕业生档案转递系统

毕业生离校档案转递的全流程演示系统：去向申报 → 院系核对 → 档案封装 → 邮寄追踪 →
退件重寄 → 签收归档。纯 Python 标准库实现（`wsgiref` + `sqlite3`），零第三方依赖。

## 一条命令启动

```bash
./run.sh                # 或 python3 app.py，默认 http://127.0.0.1:8000
```

首次启动自动建库并写入演示数据（**含拒收样例**）。其他命令：

```bash
python3 app.py advance   # 命令行推进一次模拟物流（可观察拒收样例触发）
python3 app.py reseed    # 重建演示数据
python3 -m unittest discover -s tests -v   # 运行测试（19 个用例）
```

## 业务规则

- 一名学生同一毕业批次只允许一份有效转递单（数据库部分唯一索引兜底）。
- 地址变更须在**寄出前**完成院系复核；寄出后地址锁定，只能由档案室启动
  **退回重寄**（重寄运单与原运单挂接成退件链）。
- 拒收、封签破损、材料缺页、物流滞留、同名混淆五类异常各有独立处理流程：
  拒收→退回重寄；破损→重新封装换发封签号；缺页→补齐或豁免；滞留→催办；
  混淆→身份核验（姓名+学号+身份证后四位）。
- **职责分离**：院系不得查看档案袋内敏感材料；缺页豁免由档案室发起、院系审批，
  档案室（包括非申请人的其他档案员）无权批准。
- 证明材料落盘前自动遮罩（身份证、手机号），本地只保存遮罩后的版本；
  界面敏感字段默认遮挡，仅学生本人与档案室可临时显示。

## 技术结构

```
app.py                 入口：serve / advance / reseed
run.sh                 一键启动
archive_app/
  db.py                SQLite schema（转递单/运单/物流事件/异常/豁免/材料/转递链审计）
  domain.py            状态机与全部业务规则（测试覆盖的核心）
  logistics.py         模拟物流适配器（normal / rejected / stalled 脚本）
  masking.py           敏感字段遮罩
  seed.py              演示数据（经 domain 层写入，转递链完整）
  web.py               WSGI 路由与三端处理器
  views.py             页面渲染（白/深灰/校园蓝，敏感字段默认遮挡）
  static/style.css
tests/test_domain.py   身份匹配、地址锁定、退件重寄、职责分离等 19 个用例
data/                  运行期生成：archive.db 与遮罩后的证明材料
```

物流为模拟适配器，不访问外部服务；演示环境免密码，会话仅用于角色切换。
