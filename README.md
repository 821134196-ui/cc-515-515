# 毕业生档案转递系统

毕业生离校档案去向申报 → 院系核对毕业状态 → 档案室封装封签 → 寄出物流跟踪 → 异常处置 → 退回重寄 → 签收归档的全流程演示系统。纯 Python 标准库 + SQLite + 原生前端，零第三方依赖。

## 一条命令启动

```bash
./run.sh
# → 重置并播种演示库（含拒收样例），启动 http://127.0.0.1:8000
```

## 拒收样例走法

1. `lixue` 登录 → 看到接收单位、当前节点（已退回待重寄）与原运单 `SF20250004`；
2. 「申请退回重寄」填写新接收信息；
3. `dept01` 院系端 →「地址/重寄复核」→ 复核通过；
4. `arch01` 档案室端 → 打开单据「重新加封」（新封签 `FQ2025-0004-R2`）→「待寄出」选 normal 寄出；
5. 推进物流到签收：原运单与重寄运单 **并排显示为退件链**，单据归档。

## 核心规则（均有测试覆盖）

- **去向申报**：接收单位/地址/接收人/电话/报到材料；同一学生同批次仅一份有效转递单（DB 部分唯一索引），作废后可重新申报；重寄沿用原单、生成新运单腿。
- **院系核对**：通过才进入封装；不通过则作废。
- **地址锁定**：寄出前更正须学生申请 → 院系复核（封装前必须办结，有待复核变更不能封装）；已封装/寄出后只能退回重寄。
- **封装清单**：档案室生成封签号并记录袋内材料；院系与学生只见封签号与份数，**看不到敏感材料明细**。
- **五类异常单独处置**：
  - 接收单位拒收 → 物流退回 → 学生重寄申请 → 院系复核 → 档案室加封再寄；
  - 封签破损 → 退回核验内封（完好重封 / 破损开箱清点）→ 可触发缺页豁免；
  - 材料缺页 → 档案室发起豁免，**审批人批准，档案室不能自批**（也不能审批本人发起的申请）；
  - 物流滞留 → 档案室催办（恢复流转）或召回（退回重寄）；
  - 同名混淆 → 凭**身份证后四位 + 学号双因子**核对，错任一即拒，通过才归档。
- **敏感信息**：身份证/手机/银行卡号落盘前正则遮罩，`data/proofs/` 中只有脱敏副本；接口默认只回传身份证后四位，完整号仅档案室/审批人可见。

## 测试

```bash
python3 -m unittest tests.test_archive -v
```
覆盖：身份匹配（含错误因子拒绝）、地址锁定与复核、退件重寄运单链、职责分离（院系隔离 + 豁免审批分离）、五类物流剧本、脱敏落盘、HTTP 权限状态码。

## 结构

```
app/
  config.py    路径/端口/物流场景
  db.py        SQLite schema（转递单/事件链/变更/封装/运单链/异常/豁免/材料）
  shipping.py  模拟物流适配器（normal/refuse/damage/stagnant/confusion 剧本）
  service.py   状态机 + RBAC + 异常处置（全部业务规则）
  proofs.py    证明材料脱敏落盘
  seed.py      12 名学生 × 五类异常演示数据
  server.py    stdlib HTTP：JSON API + 静态文件
  static/      原生 SPA（白/深灰/校园蓝，敏感字段默认遮挡）
run.sh         重置播种 + 启动
tests/         unittest 测试
```
